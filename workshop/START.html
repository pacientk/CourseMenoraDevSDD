SDD Workshop — dry run

Thank you for testing the workshop before the real meeting. You play a participant: you go through the same steps, with the same prompts, on your own machine, and you write down what did not work, what was unclear and how long each step took. Your run also produces the checkpoints the group will use to catch up.

Time budget. The meeting is 105 minutes; the hands-on part (steps 1–7) is about 95 of them. Expect your dry run to take 2–3 hours including notes. You do not have to finish in one sitting — the project state lives in git and the documents, and every step starts a new chat.

1. Set up (step 0)

  1. Install Node.js 22.12+, Git, VS Code with the GitHub Copilot and GitHub Copilot Chat extensions, and sign in to GitHub in VS Code.
  2. Clone the repository and check the machine:
git clone https://github.com/pacientk/CourseMenoraDevSDD.git
cd CourseMenoraDevSDD
npm install
npm run doctor

Note the doctor output in your feedback, including anything you had to fix.

2. Go through the steps

Open workshop/prompts.html in a browser, choose your operating system at the top, and follow steps 1 → 7 in order. Copy the prompts from the page, do not retype them. Read what Copilot asks before you press Allow or Keep — count how many times it asked.

Rules of the run:

  • Use the prompts as written. If one does not work and you had to rephrase it, write down both versions.
  • Keep the --commit flag on: we build the group's checkpoints from your commits.
  • If a step fails, try the "If it did not work" box of that step first. Write down whether it helped.
  • Do not fix the repository yourself (rules, skill, agents) — report instead. Fixing the application code by hand is fine when the fallback box says so.
  • Step 8 (SPEC-003) is optional.

3. Write the feedback

Fill in workshop/FEEDBACK.md as you go — one block per step: time, number of approval prompts, what went wrong, what was unclear, a verdict. Honest and specific beats polite: "the agent asked a question I could not answer" with the question quoted is exactly what we need.

4. Send it back

When you are done, pack the whole git history (all branches, all commits) into one file and send it together with workshop/FEEDBACK.md:

git bundle create sdd-dry-run.bundle --all

The file appears in the repository root. If you prefer, push your branches to a fork on GitHub and send the link instead.
