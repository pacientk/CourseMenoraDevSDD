# Бриф — профиль клиента на странице «תמונת לקוח 360»

Это вводная от продукта: сырой материал, из которого скилл `sdd` собирает эпик.
Здесь нет критериев приёмки и нарезки на задачи — их формулирует спека.

## Зачем

Сотрудник сервисного центра во время звонка должен за секунду увидеть, с кем он
говорит и какие задачи по клиенту открыты. Сейчас страница клиента пустая: есть
только заголовок (SPEC-001).

## Что нужно

1. **Карточка клиента.** Аватар, полное имя, номер клиента, телефон, электронная
   почта, город. Блок «פרטי לקוחה» на скриншоте `docs/design/customer-360.png`.
2. **Задачи по клиенту.** Карточка со списком задач: текст задачи и её статус —
   открыта или выполнена. По мотивам блока «פניות אחרונות» на скриншоте.
3. Клиент определяется адресом страницы: `/customers/1`, `/customers/2`.

## Откуда данные

Открытый API DummyJSON, базовый адрес — в `VITE_API_BASE_URL`.

- `GET /users/{id}` — профиль. Нужны: `id`, `firstName`, `lastName`, `phone`,
  `email`, `image`, `address.city`. Несуществующий клиент — ответ `404`.
- `GET /users/{id}/todos` — задачи: `{ todos: [{ id, todo, completed, userId }], total, skip, limit }`.
  У клиента может не быть задач — тогда `todos` пустой.

**Важно.** Ответ `/users/{id}` содержит и то, что показывать нельзя: `password`,
`ssn`, `bank` (номер карты, IBAN), `ip`, `macAddress`, `crypto`. Эти поля не должны
попадать ни на экран, ни в модель приложения, ни в логи.

## Как должно себя вести

- Пока данные грузятся — видно, что идёт загрузка, а не пустая карточка.
- Клиента нет (`404`) или в адресе не число (`/customers/abc`, `/customers/0`) —
  сообщение «הלקוח לא נמצא». Для некорректного адреса запрос к серверу не уходит.
- Сервер недоступен или вернул ошибку — сообщение «לא הצלחנו לטעון את הנתונים» и
  кнопка «נסו שוב», которая повторяет запрос.
- Ответ сервера неожиданной формы (нет обязательных полей) — это ошибка, а не
  пустая карточка и не падение страницы.
- Карточка клиента и карточка задач независимы: если задачи не загрузились,
  карточка клиента всё равно показана, и наоборот.
- Аватар показываем, только если адрес картинки начинается с `https://`. Иначе, и
  если картинка не загрузилась, — инициалы клиента.
- Сотрудник быстро переключается между клиентами: поздний ответ по прежнему клиенту
  не должен перезаписать данные текущего.

## Тексты интерфейса (иврит)

| Назначение | Текст |
|---|---|
| Имя карточки клиента | פרטי לקוח |
| Подписи полей | מס׳ לקוח · טלפון · דוא״ל · עיר |
| Загрузка карточки | טוען פרטי לקוח |
| Заголовок карточки задач | משימות טיפול |
| Статусы задачи | פתוח · בוצע |
| Загрузка задач | טוען משימות |
| Нет задач | אין משימות ללקוח |
| Клиент не найден | הלקוח לא נמצא |
| Ошибка загрузки | לא הצלחנו לטעון את הנתונים |
| Повторить | נסו שוב |

## Не нужно сейчас

- Поиск другого клиента (будет отдельной спекой).
- Претензии, полисы, льготы, документирование разговора, предложения.
- Редактирование данных клиента.
- Год присоединения и статус «מבוטחת פעילה» — в API таких полей нет.
- Кэширование, пагинация задач, тёмная тема.

## Ограничения

- Новые пакеты не добавляем: только то, что уже установлено.
- Конвенции проекта — `docs/architecture/conventions.md`.
- Работа должна раскладываться на задачи, которые можно исполнять параллельно.
