Every command and prompt of the meeting, step by step. Terminal blocks run in the VS Code terminal; Copilot Chat blocks are pasted into the Copilot Chat panel in Agent mode. The toolbar at the top follows you: switch Windows / macOS there — it changes shortcuts, shell commands and shell names on this page.

Working with Copilot during the workshop. Open Copilot Chat with Ctrl+Alt+I⌃⌘I, pick Agent in the mode dropdown, and start a new chat at every step marked "new chat". When Copilot asks to run a terminal command, read it and press Allow — the gate and git commands are pre-approved in .vscode/settings.json, anything else is worth a glance. Step 0 — Before the meeting

You need Node.js 22.12 or newer, Git and VS Code with the GitHub Copilot and GitHub Copilot Chat extensions. Installers: nodejs.org, git-scm.com, code.visualstudio.com — or from the terminal:

Terminal 
winget install OpenJS.NodeJS.LTS Git.Git Microsoft.VisualStudioCode
brew install node git
brew install --cask visual-studio-code

Open a new PowerShell window afterwards so the new tools are on the PATH. If PowerShell refuses to run npm ("running scripts is disabled"), run once: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.

On macOS the code command is not on the PATH by default: in VS Code open the Command Palette (⇧⌘P) and run Shell Command: Install 'code' command in PATH once.

Then clone the course repository:

Terminal 
git clone https://github.com/pacientk/CourseMenoraDevSDD.git
cd CourseMenoraDevSDD
npm install
npm run doctor

npm run doctor must end with Ready. An [INFO] line about the react-engineer agent is expected: we create it during the meeting. A [WARN] about the API means your network blocks dummyjson.com — the project has an offline copy, you will use npm run dev:offline.

Open this page from the clone so the links and copy buttons work locally:

start workshop\prompts.html
open workshop/prompts.html

Then open the project in VS Code:

code .

VS Code will ask whether you trust the folder — choose Yes, I trust the authors; agents, skills and prompt files do not load in restricted mode. Accept the recommended extensions (GitHub Copilot, GitHub Copilot Chat) if prompted, and sign in to GitHub.

Step 1 — Start Copilot, check the agents and the skill

Open Copilot Chat (Ctrl+Alt+I⌃⌘I) and select Agent mode. Type / in the input: the list must contain /sdd, /review and /security-review. Open the agent dropdown: it must contain code-reviewer. Everything came with the repository — .github/skills/, .github/agents/, .github/prompts/.

Copilot Chat — getting to know the project 
Read AGENTS.md, docs/architecture/conventions.md and .github/skills/sdd/SKILL.md.
Answer briefly, as a list:
1) which gates the project has and which command closes each one;
2) who writes the code, who checks it, and why these are different roles;
3) what you must do if asked to write code without an approved spec.
Change nothing.

If it did not work

/sdd is not in the list — run Developer: Reload Window from the Command Palette (Ctrl+Shift+P⇧⌘P) and check that the folder is trusted (Manage Workspace Trust). Still missing — type the prompt in plain words instead of the slash command: "Use the sdd skill: run SPEC-001 with --commit". The skill is picked up by its description.

No Agent mode in the dropdown — update VS Code and the Copilot Chat extension; agent mode needs a current version.

Step 2 — Create the implementer agent by analogy

We have a finished agent for React Native: workshop/reference/rn-engineer.agent.md. We ask Copilot to produce an agent for this project after its pattern.

Copilot Chat — new chat 
Create an implementer agent for this project after the pattern of an existing one.

Pattern: workshop/reference/rn-engineer.agent.md — an agent for React Native that
works with the standards kit in standards/ and a project profile.

Needed: .github/agents/react-engineer.agent.md — an agent for this project (React
web, Vite, TypeScript, Vitest).

Keep from the pattern:
- the structure of steps 0–4: load the rules → methodology gate → implement →
  Definition of Done → hand-off;
- the frontmatter format (name, description, tools);
- the prohibitions: never weaken a rule to get green, never skip a gate silently,
  never fix what is outside the task's scope;
- the handling of review findings with IDs F-1, F-2.

Replace:
- the rule sources in step 0: instead of standards/ and PROJECT-PROFILE — this
  project's AGENTS.md and docs/architecture/conventions.md, plus docs/design/README.md;
- the React Native rules in step 2 — with the rules from
  docs/architecture/conventions.md tagged [Review]: what lint does not catch;
- the gates in step 3 — with the commands from the table in AGENTS.md;
- the hand-off format — with the template .github/skills/sdd/templates/handoff.md.

Remove: everything about React Native, simulators, themes.

Add:
- to step 1: the agent changes files only within the Scope paths of its task and
  never edits plan.md or review.log.md;
- to step 3: the parallel-wave rule — run tests only for its own paths, do not fix
  errors in other tasks' files, report them in the hand-off;
- to step 2: files are created and edited with the editor tools, not through the
  terminal, and only terminal commands that work in both PowerShell and zsh are used.

Frontmatter: name: react-engineer, tools: ['read', 'search', 'edit', 'execute'].
Write in English. First show a table "taken from the pattern / replaced / removed",
then write the file right away — do not wait for confirmation.

Copilot shows the new file as a pending change — read the frontmatter and step 2, then press Keep. Check: open the agent dropdown in Copilot Chat; react-engineer must be there (if not, reload the window).

Copilot Chat — the agent is now part of the project 
Commit the new agent on main with the message: chore: add react-engineer agent

If it did not work

Terminal 
Copy-Item workshop\fallback\agents\react-engineer.agent.md .github\agents\react-engineer.agent.md
cp workshop/fallback/agents/react-engineer.agent.md .github/agents/react-engineer.agent.md

Step 6 — Independent review and the fix loop

Copilot Chat — new chat, round 1 (gate G5). The reviewer runs as the code-reviewer agent, has no editing tools and changes nothing in the project. 
/review task: docs/specs/SPEC-002-customer-profile/epic.md

Read the report: the verdict, the acceptance-criteria table, the findings F-1….

Copilot Chat — fixes from the report (same chat, so the orchestrator sees it) 
/sdd fix SPEC-002

The orchestrator records the round in review.log.md, passes the findings to the react-engineer agent, re-runs the gate and prints the ready re-review command.

Copilot Chat — round 2 (use the command /sdd fix printed; usually this one) 
/review re-review: previous findings — docs/specs/SPEC-002-customer-profile/review.log.md, round 1; task: docs/specs/SPEC-002-customer-profile/epic.md
Copilot Chat — record the result of round 2 
/sdd fix SPEC-002

Verdict APPROVED — the gate is closed. CHANGES REQUESTED again — the two-round limit is exhausted: the orchestrator stops and asks you for a decision. That is the correct behaviour.

Copilot Chat — record 
Commit the review fixes with the message: fix(SPEC-002): review round 1 findings
