# Hand-off исполнителя

Исполнитель возвращает этот отчёт в конце задачи. Каждый слот заполнен: пустой слот
означает, что задача не завершена. Отчёт — это утверждения, которые оркестратор и
ревьюер перепроверяют, поэтому в нём факты и реальный вывод команд, а не оценки.

```markdown
## Hand-off — {SPEC-NNN} / {T-NNN или «small spec»}: {название}

**Что сделано:** {один абзац: что изменилось и почему так}

**Файлы:**
- создано: `{путь}`, `{путь}`
- изменено: `{путь}` — {что именно}

**Критерии приёмки:**
| AC | Реализован | Тест (файл → имя теста) |
|---|---|---|
| AC-1 | да | `src/…/__tests__/X.test.tsx` → "shows …" |

**Гейты — реальный результат каждой команды:**
| Гейт | Команда | Результат |
|---|---|---|
| Типы | `npm run typecheck` | {exit 0 / первая ошибка} |
| Линт | `npm run lint` | {0 ошибок, N предупреждений} |
| Тесты | `npm run test` | {N файлов, M тестов, все зелёные} |

**Дополнительные сценарии:** {найденные граничные случаи и тесты на них — или «нет»}

**Проверка в браузере:** {что открыл и сверил — или
«не удалось проверить UX — нужен взгляд человека на <маршрут>»}

**Отклонения от конвенций:** {правило, место, обоснование — или «нет»}

**Найдено, но не тронуто:** {дефекты и сомнения вне границ задачи — или «нет»}

**Ответы на находки ревью** (только в раунде исправлений):
| ID | Статус | Где / доказательство |
|---|---|---|
| F-1 | fixed / answered / disputed | {…} |

**Строка для журнала прогресса:** {T-NNN | волна | completed / blocked | заметка}
```
