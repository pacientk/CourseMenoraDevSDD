# Menora · SDD Workshop — «Профиль клиента 360»

Учебный React-проект: страница сервисного центра «תמונת לקוח 360» (профиль клиента).
На нём проходим весь цикл Spec-Driven Development: спека → задачи → план → исполнение
агентом → независимое ревью → security → сборка.

Стек: React 19 · TypeScript (strict) · Vite · React Router · Vitest + Testing Library · oxlint.
Интерфейс — иврит, RTL. Данные — открытый API DummyJSON (`VITE_API_BASE_URL`).

## Правила

- **Spec-driven development.** Никакого кода без спеки в статусе `approved` в
  `docs/specs/`. Спеки, задачи и планы ведёт скилл `sdd` (`.claude/skills/sdd/`).
  Статус `approved` ставит только человек.
- **Роли.** Код пишет агент `react-engineer`. Проверяет независимый read-only ревьюер:
  `/reviewer:review` (плагин `reviewer`, маркетплейс `eng-standards`). Автор не
  проверяет сам себя.
- **Git.** Интеграционная ветка — `main`. Работа по спеке идёт в ветке
  `spec/NNN-slug`. Коммит, merge и push — только по прямой просьбе пользователя.
- **Зависимости.** Всё нужное уже установлено. Новый пакет — только если он назван в
  утверждённой спеке.
- **Язык.** Отвечай пользователю на русском. Документы курса — на русском. Код, имена
  тестов, сообщения коммитов — на английском. Тексты интерфейса — на иврите, только из
  `src/shared/i18n/he.ts`.
- **Инструменты.** Файлы создавай и правь инструментами Write и Edit, а не через bash
  (heredoc, `sed -i`, скрипты).

## Перед тем как писать код

1. Прочитай `docs/architecture/conventions.md` — слои, компоненты, стили, данные,
   безопасность, тесты.
2. Прочитай спеку и свою задачу целиком, включая критерии приёмки и тест-сценарии.
3. Дизайн: `docs/design/README.md`. PNG — смотреть. HTML-референс — только `grep` по
   классу или селектору, **не читать целиком** (60 КБ разметки).

## Команды (гейты)

| Гейт | Команда |
|---|---|
| Типы | `npm run typecheck` |
| Линт | `npm run lint` |
| Тесты | `npm run test` |
| Все три по порядку | `npm run validate` |
| Аудит зависимостей | `npm run audit:deps` |
| Релизная проверка (validate → audit → build) | `npm run release:check` |
| Запуск | `npm run dev` · без сети: `npm run dev:offline` |
| Локальный «деплой» | `npm run build && npm run preview` |

## Никогда

- Не ослаблять линт и `tsconfig`, не пропускать и не удалять тесты ради зелёного
  результата.
- Не рендерить и не логировать поля ответа API вне белого списка
  (`docs/architecture/conventions.md § Безопасность`). API отдаёт `password`, `ssn`,
  `bank` — дальше маппера они не идут.
- Не писать цвета, размеры и пользовательские строки литералами в компонентах.
- Не менять файлы в `tools/` и `docs/design/`.
